# TED-OCC Discord 運営ドキュメント

## 1. サーバの目的

ted-occ メンバーによる**アプリケーション開発と技術情報交換**のための非公開サーバ。社内限定、メンバー招待制。

## 2. チャンネル構成

### 現状

| カテゴリ | チャンネル | 用途 |
|---|---|---|
| （なし） | `#一般` (テキスト) | — |
| （なし） | `#一般` (ボイス) | — |
| 00_運営・ルール | `#welcome` | 新メンバーへの案内、ピン留めで導線を提供 |
| 00_運営・ルール | `#rules` | サーバルール（ピン留め） |

| カテゴリ | チャンネル | 用途 |
|---|---|---|

**原則:** チャンネルは「必要になってから作る」。事前に器を増やさない。

## 3. ロールと権限

| ロール | 権限 | 担当 |
|---|---|---|
| **管理者 (Admin)** | サーバ設定変更、メンバー招待・除名、チャンネル作成・削除 | TED-Administrator、および指名された 1〜2 名 |
| **メンバー (Member)** | 全チャンネルの閲覧・投稿、ボイス参加 | ted-occ Organization メンバー |

管理者は単一障害点を避けるため**最低 2 名**を推奨。

## 4. 招待フロー

非公開維持のため、招待は以下の手順に統一します。

1. 既存メンバーが新メンバー候補を管理者に推薦（社内のどの所属か明記）
2. 管理者が `web-welcome` リポジトリでの参加申請 PR を確認
3. GitHub Organization (ted-occ) への招待と**同時期に** Discord 招待を送付
4. 招待リンクは**1 回限り・24 時間有効**で発行し、使用後は失効させる
5. 入室後、`#welcome` で自己紹介を促す

## 5. 除名フロー（退職・異動・違反時）

情報漏洩対策の要。以下のいずれかに該当したら速やかに除名します。

- 社内での所属変更により ted-occ 対象外になった
- Organization から脱退した
- ルール違反が繰り返された

**手順:** 管理者が Discord サーバから除名 → GitHub Organization からも除名 → 管理者間で完了を相互確認。

## 6. ログ・履歴の扱い

- Discord の標準機能としてメッセージ履歴は保持される前提
- 機密性の高い情報はそもそも投稿しない（`#rules` の規定 1 に従う）
- 重要な決定事項は Discord に流さず、GitHub Issue / PR / README に残す

## 7. メンテナンス

- **月次**: 管理者が在籍メンバー一覧を Organization と突き合わせ、乖離があれば除名
- **都度**: ルール・運営ドキュメントの改訂は PR ベースで行い、改訂履歴を git に残す
